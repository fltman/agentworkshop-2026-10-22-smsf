# β gen-002: scenario conformance runner, built

## What was built
- `board/plugins/tompa/scenario.js`: `createRunner(deps, opts)` runs the 6 steps (happy path, SMS_NOT_ALLOWED,
  MO_SMS_BARRED, MT-barred UE4, MWD + alert, USER_UNKNOWN). The UE simulator comes in as injected deps, so it is
  tested with stubs and a virtual clock. Each row: `{step, name, expected, got, verdict, hop, owner, report}`.
- Hop/owner reuse α's `diagnose.smsfResponse` (EXPECTED map + blame on cause/detail). MT failures use α's N1N2
  verdict from the AMF log when the MT reached us malformed, otherwise "SMSC→SMSF→AMF (MT leg)" on krilju.
- `index.js`: `POST /scenario/run[?step=N]`, `GET /scenario`. Drives the existing handlers in-process via a captured
  res/req, so UE state, KPIs, the log and α's /faults all see the run. One run at a time (409).
- Tile `scenario.html` + `scenario.js`: run all or one step, verdict colours, expandable + copyable fault report.
- Tests: `projects/tompa/test/scenario.test.js` (all-pass, wrong cause → hetoteam on SMSF→UDM, MT timeout → krilju
  and step 4 inconclusive, MT delivered to barred UE4 → holminator, busy refusal, HTTP wiring). 26/26 tompa tests,
  board 163/163.

## Self-assessed fitness signals
- Faults it can find: end-to-end ones α cannot see from one boundary: missing MT delivery, wrong/missing negative
  causes, barring not applied, MWD/alert missing. Live hits: unknown until the human approves a run.
- False positives: guarded. MWD/alert not delivered → skip ("pending"), not fail. Step 4 silent non-delivery is a
  skip unless step 1 proved the MT leg works. Local AMF refusals are skips, not peer faults.
- Hop localisation: as good as α's blame text heuristics for SMSF answers; coarse for silent MT loss (whole MT leg).
- Cost: ~10 s per full run (5 s MT poll + up to 9 s MWD), a dozen requests to peers. No background traffic.
- Demo value: high, a one-button pass/fail table with ready #build drafts.

## Limits
- Still stops at the first broken hop per step; cannot tell SMSC from SMSF for a silently lost MT.
- Step 4 accepts "not delivered" as pass when no cause comes back (store-and-forward may never return one).
- Leaves test UEs registered and changes live KPIs/causes counters; step 5 toggles UE2 reachability.
